# Живий хард-тест Questionio: 45 хвилин

Цей сценарій ще належить виконати з реальним голосом через навушники.
Прискорені Swift-тести перевіряють логіку й доставку PCM із тестовим декодером;
вони не вимірюють точність Whisper, Zoom, AirPods або реальний нагрів за 45 хвилин.

Перед початком: вихід macOS — потрібні навушники; джерело — Zoom/Meet або браузер
з викладачем; Both і захоплення власного мікрофона ввімкнені. Вибрати доступний
мікрофон. Mathematics, папка lab1_iad_pharmacy, Automatic answers OFF, Ghost ON.
Другий учасник говорить спонтанно, а спостерігач фіксує очікувані питання та час.
В аудиторії один мікрофон не розрізняє людей автоматично: «Я говорю» — ручна пауза.

| Час | Сценарій | Що звірити |
|---|---|---|
| 0–5 хв | Короткі визначення: ексцес, асиметрія, n−1, γ/α | Терміни, формули, джерела голосу, питання в списку |
| 5–10 хв | Довгий опис задачі, потім питання; паузи 0.5/1/3/6 с | Передумова залишається в контексті; незавершена чернетка не отримує автоматичної відповіді |
| 10–15 хв | «Чому ділимо на… стоп, краще поясніть, чому 72 і 63 залишили?»; «ні, точніше…» | Стани перерване/переформульоване, активним є нове питання, застаріла автовідповідь скасовується |
| 15–20 хв | Власна відповідь поверх голосу викладача, потім уточнення | Канали не змішуються; репліка студента не дописується до питання викладача |
| 20–25 хв | Формули в коді, зміна файла, спонтанне питання про конкретний рядок | Вірний файл, точна формула й позначення, LaTeX; не змішувати аптеку й ліфт |
| 25–30 хв | Перемкнути вихід на інший пристрій і назад; коротке відключення навушників | Захоплення відновлюється; попередні PCM/текст не очищаються; помилки видно |
| 30–40 хв | Репліки 30–80 с, швидкі питання, мовчання, відмова від питання без слова «стоп» | Розмір черги, паузи/уточнення, якість локального аналізу; натискання на старі питання дає їхній контекст |
| 40–43 хв | Повернутися до факту з першої хвилини | Пошук у повному текстовому журналі знаходить ранню репліку |
| 43–45 хв | Stop, дочекатися завершення Whisper, експорт; перезапуск і «Відновити останній» | Усі завершені репліки й питання відновилися, файл експорту містить початок і кінець |

## Звіт і критерії

- Звірити всі контрольні питання із транскриптом; окремо рахувати спотворені
  математичні терміни й пропущені питання. Помилки не приховувати за перефразуванням.
- Зафіксувати розриви захоплення, нерозпізнані фрагменти, повторні спроби декодера,
  найбільшу чергу, RSS процесів і використання тимчасового кешу. Наприкінці кеш
  нормального сеансу має бути порожній.
- Записати час кінця репліки → готове питання, клік → перший токен і повна відповідь;
  подати p50/p95/max. Ціль 1–3 с для першого токена — критерій вимірювання, не обіцянка.
- Для кожного переривання перевірити, яке питання реально було обране й чи
  не відповіла програма на покинуту чернетку. Неявна зміна наміру може бути
  класифікована хибно — ручний вибір залишається доступним.
- Прогін не зараховується як безперервний, якщо стався виліт, непомітна втрата
  тексту, зупинка захоплення без повідомлення чи неможливість відновити журнал.
  Будь-які зафіксовані gaps потребують пояснення та повторного прогону після виправлення.

Текстовий журнал зберігається локально лише при Save history ON. Аудіокеш —
тимчасова черга під навантаженням, не повний аудіозапис для порівняння. За потреби
еталонний запис тесту треба окремо погодити з учасниками й налаштувати перед прогоном.

Автоматизована частина: `swift test --filter DialogueReliabilityTests`.
